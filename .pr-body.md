## Spike: hybrid graph projection-reader (issue #43 — "ours in front, theirs underneath")

Implements the endorsed verdict from the issue #43 head-to-head: a **reader**
that projects an upstream-built in-engine code graph (zvec-ai/zvec-grep
origin/main @7504720, `zg --index --graph`) into our `codegraph-v2` sidecar
format, so our MCP/CLI query surface consumes an integrated-substrate graph
**without migrating**. A spike: a reader, not a migration.

### What's here

- **New crate `rust/crates/zg-graph-projection`** (lib + `zg-graph-project`
  binary): reads upstream's `.zvec-grep/index` store — `graph/graph.sqlite`
  (edge table with status/provenance/candidates), the `entities/` zvec
  collection (symbol metadata + source ranges), and the `files/` zvec
  collection (paths + content hashes) — and writes a codegraph-v2 artifact.
- **`zg-codegraph::write_codegraph_artifact()`** — new public API for external
  producers to serialize artifacts to an explicit path (no publication
  manifest; the producer vouches for the artifact).

### Mapping design (upstream store -> codegraph-v2)

| upstream | ours |
|---|---|
| zvec entity id (32-hex) | node id `upstream:<entity_id>` |
| file scope `f{file_id}` | node id `upstream:f{file_id}` (kind `file`) |
| `Function` + scope | kind `method`, Go qualified name `Receiver.Method` |
| `Function` without scope | kind `function` |
| payload `source_range` | node range |
| files snapshot hash/size | file sha256/bytes |
| kind calls/contains/imports/implements | same |
| kind `extends` | `inherits` |
| kind `declares` | dropped (resolver-internal binding evidence) |
| status `resolved` + provenance | `resolved=true`, `resolution="upstream:<provenance>"` — their 9-value provenance **reaches a consumer surface for the first time** |
| status `pending` (+ candidates) | `resolved=false`, `target_name`, `ambiguous_candidates` -> possible graph |
| status `failed` | `resolved=false`, `resolution="upstream:failed"` |

**Definite/possible separation survives**: resolved edges feed the definite
call graph; pending-with-candidates feed the possible graph
(`possible_callers_by_depth`); honest non-assertions stay unresolved, never
guessed. This directly answers the #43 finding that upstream's internal
certainty never leaves the engine.

### Validation (the gate) — helios08, upstream's indexer building the stores

Frozen Go fixtures, upstream zg 0.3.1 (@7504720) builds the index, projection
reads it, our `CallGraphIndex` answers, adjudicated against compiler RTA truth
(`go-graph-truth-v1`):

| Fixture | upstream reference (#43) | projection via our surface |
|---|---|---|
| tuning `go-workflow-discovery-v1` (18 edges) | 100% P / 100% R | **18/18 confirmed — 100% P / 100% R**, 0 flips |
| holdout `go-inventory-audit-v1` (17 edges) | 100% P / 88.2% R | **16/16 confirmed — 100% P / 94.1% R**, 0 flips |

The one holdout miss is `CheckAccess -> AssetState.Contains` — upstream's own
honest miss (context-helper receiver type, stored `pending`, no guessed
target). **The projection preserves their 100% precision and their recall
exactly; nothing is lost in translation.**

### Complementarity union (holdout)

Our native resolver and upstream's miss *different* edges — ours misses
`CheckAccess -> AssetState.Contains`, theirs misses
`HandleSelectAsset -> CheckAccess`. Union of the two resolved edge sets:
**17/17 truth edges at 100% precision** (report-level union over the two
artifacts; see verification log).

### Verification

- `cargo fmt` clean, `cargo clippy --all-targets` clean (workspace pedantic
  lints), 13 new tests green: mapping unit tests (status/kind/provenance ->
  our edge contract, definite/possible split) + end-to-end integration over a
  synthetic upstream store seeded exactly like upstream's writer, queried
  through `CallGraphIndex` (blast-radius, method mapping, round-trip through
  the standard artifact reader, determinism across runs).
- Full end-to-end on helios08: upstream zg built from origin/main @7504720,
  both fixtures indexed by **their** indexer, projected by **our** reader,
  adjudicated against both truth files.

### Not covered (follow-up work)

- **9-language breadth**: the reader projects whatever their indexer extracted
  (C, C++, Go, Java, JS, PHP, Python, Rust, TS); only Go is fixture-validated
  (the frozen four-language fixtures contain no source files).
- **Freshness**: the reader projects a store someone else built; regenerating
  the sidecar on upstream index changes is follow-up work.
- **zvec version coupling**: cargo's `links` rule allows one native zvec per
  build graph, so the reader uses the workspace's zvec-rust 0.7.2 to read
  0.8.1-written collections (works on the fixtures; a future upstream format
  change would need a reader update).
- Edge byte offsets (upstream records line/col only; ranges carry line/col
  with zero bytes, documented).

Closes the spike scope of #43's verdict; see

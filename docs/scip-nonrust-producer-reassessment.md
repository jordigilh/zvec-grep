# Go, TypeScript and Python SCIP producer reassessment

**Finding (2026-09-25):** The named upstream indexers are real, installable and already generated complete indexes on all three frozen fixture lanes. Availability was never the blocker. Their published versions still emit `Document.position_encoding=0`, which the [SCIP protocol](https://github.com/scip-code/scip/blob/main/scip.proto) deliberately treats as ambiguous. A **separate, version-pinned compatibility experiment** with real astral-Unicode/CRLF producer output found *scip-typescript 0.4.0 → UTF-16*, *scip-python 0.6.6 → UTF-16*, and *scip-go 0.2.7 → UTF-8*. In particular, **Python here is UTF-16, not the proto's generic suggestion of UTF-32 for a Python-implemented producer**: `scip-python` is Pyright/Node-based. These findings make optional producer-specific snapshot ingestion plausible, not generic SCIP interoperability for arbitrary indexes. Do **not** silently change the strict default importer for encoding=0 or rewrite the original artifacts with guessed protocol values.

Official sources: [scip-go](https://github.com/scip-code/scip-go), [scip-typescript](https://github.com/sourcegraph/scip-typescript) and [scip-python](https://github.com/sourcegraph/scip-python). Registry checks at the time: latest `@sourcegraph/scip-typescript@0.4.0`, `@sourcegraph/scip-python@0.6.6`, `github.com/scip-code/scip-go@v0.2.7`. TypeScript's README supports Node **22/24**; the refreshed evaluation used an isolated Node **24.21.0** (the original Node 26.7 run was outside those published support versions). Python used 3.12.12 on `PATH` under the same isolated Node 24; the previous unsupported Python 3.14 warning disappeared, while a non-fatal empty-package-info warning remained. Go used go1.26.0. No global installer or active frontend/worktree was changed.

[`scripts/scip_compat_reassessment.py`](../scripts/scip_compat_reassessment.py) accepts encoding=0 **only** for the three exact producer name/version pairs above, records that position conversion was empirically version-pinned, verifies metadata root, full source selection/content SHA-256, project config digest, per-file IR hashes and range/UTF-8 boundaries, and abstains on unknown/mixed producer encodings. It does not edit `index.scip` or zvec defaults. When the indexer omits `SymbolInformation.kind` (TS/Python), it derives a candidate kind **only** from one independently source-backed syntax IR unit with an *identical entire declaration range and token name*. It does not fill in missing kinds by descriptor spelling. Exactly joined references were emitted into separate shadow-only Code IR v1 artifacts and passed the real runtime validator. All facts remain *experimental candidates*; this is not general authorization for `type_resolved` production facts.

Nonempty range conversion failures: **0 in all three lanes** under their *pinned* encodings. TS/Python expose raw `SymbolInformation.kind=0` on the relevant definitions; this is distinct from the eight empty module occurrences and is an independent reason not to treat the raw symbol table as a complete canonical IR. Python's 49 strict shadow facts match the bounded LSP→syntax strict join count (49/144 LSP sites); TS 8 match 8/89; Go's **18** are lower than its LSP route's 73/117 because only 27/150 Go SCIP definitions have an enclosing declaration range even though its symbol kinds are specified. The producers' reference populations differ, so these numbers are **not** comparable retrieval-quality or precision scores. In earlier ASCII-only diagnostic navigation probes, all three original producer indexes matched five authored sites, but exact body/range/kind joins have the lower counts above. TypeScript/Python emit 2/1 external base-class implementation relationships, respectively; these do not establish an independently labeled local `implements` link. Go emitted no relationships in this fixture. The source selection and config hashes are reported in the compact JSON summary.

## Reassessed architecture and hard gate

1. **Preferred producer fix:** contribute or consume upstream versions that set `Document.position_encoding` explicitly (TS/Python UTF-16, Go UTF-8 **as proven for the pinned versions**, not assumed forever). This makes the artifacts self-describing for generic consumers and eliminates the compatibility exception.
2. **Optional spike-only compatibility path:** allow the three exact producer versions/binary digests on a snapshot created by our own pinned invocation and accompanied by a signed/versioned external manifest of executable/runtime/config/dependencies, whole-selected-file-set hashes and Unicode/CRLF control evidence. Keep `encoding_method=pinned-producer-unicode-control` distinct from `producer-declared`; unknown/mixed values, changing binary/runtime, bad spans or stale roots must abstain. A SCIP file's `ToolInfo` alone does **not** record Node/Python/Go runtime binary digests or source hashes, so the artifact alone does not justify the exception. No generic `UnspecifiedPositionEncoding → guessed language default` rule.
3. **Language-specific tradeoff:** Python has a plausible static SCIP snapshot path on this fixture (49 exact joins, with external locators requiring separate attestation). Go's **published** SCIP producer resolves many more symbol sites than its enclosing declaration evidence permits under the strict IR join. **Subsequent measured follow-ups:** an [isolated upstream Go fix](scip-go-upstream-enclosing-spike.md) emits explicit UTF-8 and 31 additional valid definition enclosures; the design team then committed the missing canonical Go `type` spans and struct-field units. A [same-source v1.5 recheck](scip-go-post-code-ir-v15-revalidation.md) now validates **117/117 patched local candidates** against 18/18 stock candidates; the historical 18 for the patched producer was a v1.3-only downstream result. TypeScript still needs both explicit encoding and stronger canonical declaration/kind alignment (8 strict joins at v1.3), whether using SCIP or LSP. Rust remains a *self-describing* native SCIP candidate (explicit UTF-8 positions and 131/131 valid definition enclosing spans); see [Rust reassessment](rust-scip-reassessment.md). Full independent relation precision, dependency-complete atomic snapshot and production-default gates remain open.

## Reproduce

Start with a **new empty** isolated ROOT under the pre-approved temporary parent, then stage only Engram manifest-selected source (do not edit Engram), generate the official proto bindings, install pinned producers/tools locally and export the read-only syntax IR as documented in [`scip-code-ir-spike-results.md`](scip-code-ir-spike-results.md#reproduce). Use **Node 24**, **Python 3.12** on `PATH`, Go 1.26 and the exact producer versions above; canonicalize Python `--cwd` to avoid the observed macOS `/var`/`/private/var` zero-document failure. Run the independent controls before treating a zero encoding as a candidate:

```sh
python3 scripts/scip_nonrust_position_controls.py "$TOOL_ROOT"
python3 scripts/scip_compat_reassessment.py "$ROOT" typescript python go
IR_ARTIFACT_PREFIX=compat-v2-shadow-ir node scripts/validate_shadow_ir.mjs "$ROOT" MODULE typescript python go
python3 scripts/lsp_ir_shadow_join.py "$ROOT" --check-labels --compat typescript python go
PYTHONDONTWRITEBYTECODE=1 python3 -m unittest discover -s tests -p 'test_*.py' -v
```

`TOOL_ROOT` is the isolated root with generated `scip_pb2.py`, pinned local producers and Node 24; `ROOT` is the independently staged and indexed four-language fixture root; `MODULE` is the read-only sibling path to `dist/engine/code-ir/index.js`. All large `.scip` and shadow JSON artifacts stay in temporary roots, outside git. The commands/versions/digests in [`scip-nonrust-compat-summary.json`](scip-nonrust-compat-summary.json) identify the concrete measured run.

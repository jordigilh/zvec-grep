## Follow-up: LSP as a separate semantic fact source (not a SCIP encoding guess)

The [LSP 3.17 position contract](https://microsoft.github.io/language-server-protocol/specifications/lsp/3.17/specification/#textDocuments) is materially different from SCIP's missing-document-encoding case: a client advertises supported encodings at `initialize.general.positionEncodings`; a server's `capabilities.positionEncoding` selects one, and **omission explicitly defaults to UTF-16**. The LSP result says **nothing about** what encoding a separately generated `index.scip` used. Therefore LSP cannot safely retroactively fill in `Document.position_encoding=0`. It can, however, be an **alternative producer of semantic facts** behind a standalone adapter before Code IR sees them.

The experimental [`scripts/lsp_code_ir_spike.py`](../scripts/lsp_code_ir_spike.py) opens every selected source document from its original UTF-8 bytes in an isolated local server; requests `textDocument/documentSymbol` for every file, `textDocument/definition` for five authored sites/lane and `textDocument/references` for those five definition targets; converts response `Location`/`LocationLink` ranges from **negotiated UTF-16** to `[start_byte,end_byte)` on the original file, checks token slices and path containment, and re-hashes the full selected file set and config before publishing any output. It emits a candidate fact containing verified site and target byte spans, 1-based line/0-based byte column, per-file SHA-256, source-set snapshot key, server/version and method. `LocationLink.targetSelectionRange` is a token; `targetRange`/document-symbol range is a separate prospective enclosing body, not interchangeable. Five source sites per lane in this prototype are **authored label seeds**; the additional find-references sites are returned by LSP, not derived from SCIP or hand-coded sites. This is an external reproducible prototype, **not** a zvec integration or a claim of complete relation indexing.

**Integration boundary to consider after syntax IR conformance:** `immutable selected source snapshot + producer/config/dependency identity → optional semantic adapter (LSP; SCIP independently only if strictly encoded) → validated IR unit joins and anchored facts → separate projections`. Keep all LSP process/session lifecycle, URI resolution, position conversion and freshness checks in the adapter/sidecar; zvec consumes only versioned file-byte refs and normalized facts. A live LSP response does **not** carry an indexed commit or a transaction-wide snapshot ID, and a pre/post hash around a mutable root is not atomic proof of what the server analyzed. For a trustworthy offline build, copy/freeze the complete selected input plus relevant dependencies/config into an immutable root, pin server/tool versions and hashes, read those exact bytes into `didOpen`, attest before/after, and reject any result whose target is outside that snapshot. External targets stay locators unless their dependency source is also attested. Interactive dirty-worktree facts require generation boundaries and invalidation/rebuild on change; no stale LSP/SCIP fact may cross into a newer IR snapshot. The bounded five-target evaluation above now has a **separate full-rebuild experiment** below; it is not the full artifact's extraction limit. Retain SCIP only as a later interchange candidate once producer encodings are fixed; the prototype does not need to build it. No change to phase-3 syntax-backed IR or retrieval defaults follows from this spike.

## Freshness experiment and IR mapping

The prototype `snapshot_key` binds canonical selected path list + full per-file content digests + producer/version + configuration hash + explicit git/worktree state. `join_snapshot` rejects missing or unequal keys; it cannot prove the bytes the producer read if files change between pre/post hashing. Production attestation must take an immutable copied source root (or verify a post-build source snapshot plus stable input isolation), tie the index digest to that copy and match **the entire selected/producer-eligible file set** to IR, including dependencies/configuration or explicitly exclude unresolved targets. For a dirty worktree, a fresh index on an immutable dirty copy can be attested with content hashes and recorded branch/HEAD/dirty state; it is not a commit-pinned artifact merely because `Metadata.project_root` exists.

An unchanged repeat on Go kept 10/10 documents but changed artifact digest (`b517…` → `b58b…`). Proposed **shadow adapter only**: validate URI root, canonical regular-file relative paths and full input snapshot; read original source bytes and verify per-file digest. For a declared encoding, convert each `Occurrence.range` to token `[start_byte,end_byte)`; separately validate optional `enclosing_range`. ## Language decision and remaining gates

- **Rust: viable native SCIP snapshot producer, still shadow-only for IR integration.** The [official `scip-rust` wrapper](https://github.com/scip-code/scip-rust#readme) delegates to `rust-analyzer scip .`, which already succeeded here. All 573/573 primary byte spans validate with explicit UTF-8 encoding; **131/131 definition enclosing ranges validate**. The 150 bad enclosing ranges are *references*, so reject those expression ranges without discarding their primary token sites. A later v1.3 strict SCIP→syntax IR importer bound 34/197 selected-local normalized references (versus separately bounded LSP 49/104); both passed real runtime validation and 4/5 authored strict links. The SCIP output emitted no implementation relationship records. Treat SCIP as the Rust frozen-snapshot candidate and LSP as the live-navigation path; [details and denominator differences](rust-scip-reassessment.md). Six aggregate module-declaration manifest units still require syntax IR/file-module fallback.
- **TypeScript: real producer, generic strict SCIP import blocked, pinned-compatibility shadow candidate.** `scip-typescript@0.4.0` still emits encoding 0 even on supported Node 24; a real astral/CRLF control proves UTF-16 *for that version*. On a supported-runtime fixture rebuild, the fail-closed compatibility adapter mapped 321/329 nonempty occurrence ranges; eight allowed empty module markers are not answerable spans. Only 8 strict syntax IR reference facts and 3/5 authored strict links survived; missing fine-grained kinds and enclosing/body alignment still block broad integration. Two implementation relationships target external stdlib, not independently proven local implements facts. [Evidence](scip-nonrust-producer-reassessment.md).
- **Python: real producer, generic strict SCIP import blocked, pinned-compatibility shadow candidate.** `scip-python@0.6.6` still emits encoding 0 on supported Python 3.12/Node 24; its actual controls prove **UTF-16**, not UTF-32. The canonical-root, full-file-set compatibility experiment mapped 433/441 nonempty occurrences, backfilled fine-grained kind for 33 definitions *only* from exact source-backed syntax units, and produced 49 strict shadow facts with 5/5 authored strict links. Nineteen external symbols are locators, not local definitions. Prefer upstream explicit encoding and complete provenance before generic import. [Evidence](scip-nonrust-producer-reassessment.md).
- **Go: real producer, prototype upstream change now passes the committed v1.5 strict join.** Published `scip-go@0.2.7` emits encoding 0, proven UTF-8 for its pinned binary; it has 27/150 definition enclosures and yields 18 strict selected-local refs. A **tested but unmerged** upstream-main prototype declares UTF-8 and raises valid enclosing ranges to 58/150 without changing any primary sites. The committed v1.5 IR's Go type/field units now strictly join **117/117 patched selected-local normalized reference candidates**, compared with **18/18 stock** under the same v1.5 read-only tool. Neither number covers all 321 raw SCIP references or independently proves their global precision. No local implementation relationships were emitted. See [producer evidence](scip-nonrust-producer-reassessment.md), [upstream fix spike](scip-go-upstream-enclosing-spike.md), and [committed-IR revalidation](scip-go-post-code-ir-v15-revalidation.md).

Additional gates: authored exact declaration spans/kinds for **all** 143 manifest units (currently 20 selected declaration-token labels, not 143 unit body spans), full site-level inventories including **negative**, dynamic, implementation and external-reference cases rather than only selected successful sites; true verified/false/ambiguous/unresolved whole-corpus denominators; external-package and deleted/renamed-target producer runs; Unicode and CRLF **SCIP producer-generated** controls (the LSP path now has a real TS producer control); atomic producer-input and dependency attestation and clean/dirty revision provenance. The direct LSP comparison and standalone LSP-byte adapter narrow the reference and encoding gaps but do not substitute for independent whole-corpus ground truth. Only then consider an optional same-engine, same-language ranking ablation, separate from extraction correctness.

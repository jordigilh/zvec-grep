A fresh dirty-worktree LSP run was not needed to test that rejection.

On all four real pairs of unchanged artifacts, `--tamper-probe LANGUAGE` additionally rejected a changed staged root, a changed producer config hash and a forged cross-file IR target digest; forging one LSP site digest rejected that site and reduced emitted facts by one, not by silently redirecting it. Unit tests also cover missing/deleted targets, unique smallest-source ownership, equal-span ambiguity, modifier/body and kind mismatch, Unicode/CRLF ranges, wrong URI and split-surrogate rejection. **Remaining freshness caveat:** these staged snapshots are verified pre/post but an LSP response is not an atomic transaction or a dependency-complete snapshot. A production adapter should index from an immutable source/dependency copy and version every server/config dependency before promotion.

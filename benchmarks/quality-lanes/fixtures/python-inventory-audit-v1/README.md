# Synthetic Python Inventory Audit Fixture (HOLDOUT — never tuned on)

Holdout fixture for issue #68 (fusion recall trade), validating
generalization of any arm tuned on `python-workflow-discovery-v1`. It
mirrors `go-inventory-audit-v1` — the Go holdout for the same trade —
domain-for-domain and query-archetype-for-query-archetype, while staying
schema-identical to the Python tuning fixture. **It has never been tuned
on and must stay untouched by any tuning loop.**

Domain: inventory audit with permission enforcement — an inventory
registry is scanned, scanned-asset membership is tracked in shared state,
tag hints become scan filters, permission policy gates ledger writes and
selection, and audit review rechecks trust-ledger coverage before the
final summary is assembled.

## Protocol

- **Source-authored truth**: the relevance judgments in `truth.json` were
  written by the fixture's source author (the same session that wrote the
  `.py` files) against the actual code, per the adjudication protocol.
  Grades 1–3 with unit-specific rationales; they are not inferred from
  any engine, indexer, or backend agreement.
- **Complete-universe qrels**: `qrels.json` is generated by
  `benchmarks/quality-lanes/tools/build_synthetic_qrels.py`, expanding the
  source-authored targets to the complete 45-unit universe per query
  (`judgment_status=adjudicated`, `candidate_pool_complete=true`,
  `source_truth=true`); every unjudged unit is an explicit grade-0
  negative.
- **Exact spans**: every manifest `start_line`/`end_line` was computed
  programmatically from the written sources and validated so that each
  unit's defining statement (`class X`, `def y`, or `name =`) falls
  within its span.

Unit IDs are qualified source symbols such as
`inventory/state.py::ScanState.add` (path::Class.method, lowercase
method names), matching the `python-workflow-discovery-v1` convention.

## Design rationale

- **Domain shift**: inventory audit with permission enforcement instead
  of workflow discovery. Same shape (scanner → shared membership state →
  tag-to-filter conversion → permission-gated selection → audit ledger →
  final summary) so the Go holdout's query archetypes transfer, with zero
  vocabulary overlap with the tuning fixture.
- **Same scale class**: 10 Python files, 45 manifest units, 8 queries,
  ~300 source lines — matching the Go holdout (10 files / 45 units / 8
  queries) and the Python tuning fixture's class (8 files / 33 units /
  8 queries).
- **Schema-faithful**: `manifest.json`, `truth.json`, `qrels.json`
  mirror the Python tuning fixture field-for-field (schema_version 1,
  language "python", source `synthetic/python-inventory-audit` revision
  `fixture-v1`, include `**/*.py`, exclude `**/test_*.py`).

## Deliberate hard cases (mirroring `go-inventory-audit-v1`)

1. **Same-named module-level function vs method** (the
   `ListWorkflows`/`ListAssets` collision class):
   `tools/list_assets.py::list_assets` (module function) calls
   `inventory/registry.py::AssetRegistry.list_assets` (method); the bare
   name `list_assets` is shared across modules, so unique-index-symbol
   resolution must treat the call edge as ambiguous.
2. **Same-named symbols in different modules**:
   `audit/review.py::check_access` (module function) and
   `permissions/enforcer.py::Enforcer.check_access` (method) share the
   bare name `check_access`; `tools/select_asset.py` calls the review
   one while the enforcer method is reachable from the same file.
   `inventory/registry.py::Asset` is type-mentioned in
   `tools/list_assets.py`, `tools/select_asset.py`, and (TYPE_CHECKING)
   `inventory/filters.py` beyond its home module.
3. **Public/private mix**: module-private `_asset_in_scan_result`,
   `_authorize_access` (tools), `_scan_state_key` (state),
   `_review_budget` (review); public functions, methods, dataclasses,
   and a public exception type with `__init__`/`__str__`.
4. **Type mentions in constructors** (type-mention false-call-edge
   trap): `Permission(...)` in `PolicySet.grant`, `AuditFilters(...)` in
   `filters_from_signal`, `ScanState()` in `state_from_context`,
   `ReviewFindings(...)` in `findings_by_asset`, `AuditRecord(...)` in
   `handle_select_asset`, `AssetSummary(...)` in `apply_selected_asset`.
5. **Multi-hop recheck path**:
   `handle_select_asset` → `audit.review.check_access` →
   `state_from_context` → `ScanState.contains` (plus
   `AuditLedger.entries`).
6. **Empty-scan fail-closed path**: an empty `ScanState` makes
   `ScanState.contains` false, which fails `audit.review.check_access`
   and `_authorize_access` before any registry lookup.
7. **`_review_budget` declared at the end of `audit/review.py`** on
   purpose, mirroring the Go holdout's `reviewBudget` placement: a
   module-level assignment directly above a `def` makes line-span
   inference swallow that def's declaration. Trailing placement keeps
   the private-constant unit without span overlap.

## Adjudication notes

Mirroring the Go holdout's deliberate calls:

- Q2 (`deny-unpermitted-asset`) leaves
  `tools/select_asset.py::_authorize_access` at grade 0: that guard
  rejects *scan-result membership + asset:select permission* failures,
  not the *policy-never-granted* failure the query asks about.
- Q3 (`forward-tags-to-scan`) leaves `inventory/filters.py::ScanSignal`
  at grade 0: the query asks about the conversion path, not the raw
  signal shape.
- Q2/Q6 judgment overlap (`Enforcer.require_permission`,
  `Enforcer.check_access`, `AccessDenied` are relevant to both) is
  accepted knowingly: the two queries ask about the same enforcement
  machinery from different entry points (selection denial vs ledger
  write), mirroring the tuning fixture's analogous overlap.
